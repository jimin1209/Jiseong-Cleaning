# 지성크리닝 홍보 웹사이트

거래처(사업장)를 대상으로 지성크리닝을 알리고 **견적 문의를 받는** 홍보 사이트입니다.
발주·정산 시스템(`Document/명세서.md`)과는 별개이며, 이 사이트는 그 시스템으로 들어오는
**입구**에 해당합니다 — 문의가 접수되면 관리자가 거래처로 등록하는 흐름입니다.

가정(아파트·빌라) 세탁물은 다루지 않습니다. 사업장 고객 전용입니다.

---

## 빠른 시작

```bash
cd website
npm install
cp .env.example .env.local     # 값 채우기 (아래 참고)
npm run dev                    # http://localhost:3000
```

`npm install` 뒤에 바로 `npm run dev` 하면 됩니다. Pretendard 폰트는 `predev` 훅이
`node_modules` 에서 꺼내 배치하므로 별도 준비가 필요 없습니다.

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm run build` | 운영 빌드 |
| `npm start` | 빌드 결과 실행 |
| `npm run lint` | ESLint |
| `npm run typecheck` | 타입 검사 |
| `npm run setup:fonts` | 폰트 재배치 (predev·prebuild 가 자동 실행) |

## 기술 구성

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 프레임워크 | Next.js 16 (App Router) | `결정사항.md` 에서 데모·정식 거래처 웹 모두 Next.js 로 확정 |
| 언어 | TypeScript | 동일 |
| 스타일 | Tailwind CSS v4 | 토큰을 `@theme` 한 곳에 모아 브랜드 규격과 1:1 대응 |
| 폰트 | Pretendard Variable (자체 호스팅) | CDN 장애 시 본문이 통째로 대체 폰트로 떨어지는 것을 막음 |
| 폼 검증 | zod (서버) | 화면에서 온 값을 신뢰하지 않는다 — 설계서 1.3 원칙 |
| 문의 저장 | `node:sqlite` (Node 내장) | `결정사항.md` 의 SQLite 확정과 일치. 네이티브 빌드 의존성 없음 |
| 문의 알림 | nodemailer (SMTP) | 회사 메일·네이버·구글 모두 지원. 계정 미설정 시 조용히 건너뜀 |
| 모션 | IntersectionObserver 12줄 | 필요한 동작이 하나뿐이라 라이브러리를 넣지 않음 |

## 환경변수

`.env.example` 을 `.env.local` 로 복사해 채웁니다.

### 필수

| 변수 | 설명 |
| --- | --- |
| `NEXT_PUBLIC_SITE_URL` | 사이트 주소. `sitemap.xml` · OG 태그 · 구조화 데이터가 이 값을 씁니다 |
| `ADMIN_USER` / `ADMIN_PASSWORD` | `/admin` Basic 인증. **둘이 비면 `/admin` 은 503 으로 완전히 막힙니다** |

기본 비밀번호를 두지 않은 것은 의도입니다. 기본값이 있으면 그게 그대로 운영에 올라갑니다.

### 선택 — 문의 알림 메일

`SMTP_HOST` · `SMTP_USER` · `SMTP_PASS` · `INQUIRY_TO` 가 **모두** 채워지면 접수 시
담당자에게 메일이 갑니다. 하나라도 비면 저장만 하고 조용히 넘어갑니다.
메일 발송이 실패해도 접수는 취소되지 않습니다 (저장을 먼저 하기 때문).

## 배포

이 사이트는 **정적 파일이 아닙니다.** 견적 폼 접수, 문의 저장, 관리자 인증이
서버에서 돌아가므로 HTML 폴더만 올리는 방식으로는 동작하지 않습니다.
Node.js 20 이상이 필요합니다.

### 방법 1 — 폴더를 올려서 직접 실행 (사내 서버 · VPS)

```bash
npm ci
npm run build
npm run pack     # → deploy/ 폴더가 만들어진다 (약 25MB)
```

**`deploy/` 폴더만** 서버에 올리고:

```bash
node server.js   # 기본 3000번 포트
```

`node_modules`(약 500MB)나 `.next`(약 300MB)를 올릴 필요가 없습니다. 필요한 모듈이
`deploy/` 안에 이미 들어 있어서 서버에서 `npm install` 도 하지 않습니다.
폴더 안에 `실행방법.txt` 를 함께 넣어 두었습니다.

포트를 바꾸려면:

```bash
PORT=8080 node server.js          # Linux · macOS
$env:PORT=8080; node server.js    # Windows PowerShell
```

환경변수는 `deploy/.env.production` 에 두거나 서버에 직접 설정합니다.
`NEXT_PUBLIC_SITE_URL` 과 `ADMIN_USER`/`ADMIN_PASSWORD` 는 반드시 지정하세요.

> ⚠️ 문의는 `deploy/.data/inquiries.db` 에 쌓입니다. 새 버전으로 폴더를 갈아끼울 때
> **이 파일을 먼저 백업해 옮기지 않으면 접수 내역이 사라집니다.**

### 방법 2 — Vercel · Netlify (폴더 업로드 없음)

저장소를 연결하고 **Root Directory 를 `website`** 로 지정하면 됩니다.
빌드 명령과 출력 경로는 자동 감지되고, `output: "standalone"` 은 무시됩니다.

단, 서버리스 환경에서는 파일 시스템이 요청마다 초기화되므로 **SQLite 저장이
유지되지 않습니다.** 아래 「문의 데이터가 저장되는 곳」을 먼저 읽으세요.

### 정적 호스팅(그누보드 서버 같은 곳)에 올리려면

가능하지만 기능을 덜어내야 합니다. 견적 폼(서버 액션) · 문의 저장 · 관리자 페이지 ·
`/admin` 인증을 모두 빼고 `output: "export"` 로 바꾸면 `out/` 폴더가 나옵니다.
그 폴더는 아무 웹호스팅에나 올라갑니다. 폼은 외부 서비스로 대체해야 합니다.

## 문의 데이터가 저장되는 곳

`.data/inquiries.db` (SQLite, gitignore 대상).

> ⚠️ **Vercel·Netlify 같은 서버리스에 배포하면 이 파일은 유지되지 않습니다.**
> 요청마다 파일 시스템이 초기화되기 때문입니다. 그 환경으로 갈 때는
> `src/lib/inquiries.ts` 의 `saveInquiry` / `listInquiries` 구현만 PostgreSQL
> (설계서 2장 권장안)로 바꾸면 되고 호출부는 손대지 않습니다.
> 그 사이에도 문의가 유실되지 않도록 메일 발송을 함께 붙여 두었습니다.

VPS·사내 서버에 `npm start` 로 올리는 경우에는 그대로 써도 됩니다.

## 디자인 규격

색·타이포·컴포넌트 규칙의 정본은 브랜드 규격서(A안 — 모회사 CI 계승)입니다.
코드에서는 `src/app/globals.css` 의 `@theme` 블록이 그 규격의 단일 출처입니다.

지켜야 할 것 몇 가지:

- 컴포넌트에 색값(`#176FC0` 등)을 직접 쓰지 말고 유틸리티(`text-brand`)를 쓴다
- 모서리 반경은 `rounded-brand`(6px) 하나. 칩·배지의 `rounded-full` 만 예외
- `text-sky`(#0084D8 · 4.0:1)와 `text-ci-cyan`(#00AEEF · 2.5:1)은 **본문 대비 미달** — 아이콘·큰 글씨 전용
- 심볼은 `<BrandMark>` 로만 쓴다. 정원(1:1)으로 늘리지 말 것(실제 비율 428.53:512)
- 워드마크는 이미지가 아니라 본문 폰트로 조판한다 (`<BrandLockup>`)
- 전화번호는 반드시 `tel:` 링크. 이미지로 넣지 말 것
- 실사 촬영 전 자리는 `<PhotoSlot>` 을 쓰고 스톡 이미지를 채우지 않는다
  — 이 사이트의 논거가 「실체 있는 업체」라서 가짜 사진은 그 논거를 무너뜨립니다

## 샘플(더미) 내용 — 반드시 읽을 것

확정되지 않은 사업 정보를 **임시값으로 채워** 완성된 화면으로 보여주고 있습니다.
빈칸이 많으면 검토가 어렵기 때문입니다. 대신 가짜 값이 그대로 배포되지 않도록:

1. 더미 값은 전부 **`src/lib/sample.ts` 한 파일**에만 있습니다
2. 켜져 있는 동안 화면 맨 위에 **「검토용 샘플」 경고 배너**가 항상 뜹니다
3. 숫자는 그럴싸하게 만들지 않고 **`0` 으로 채웠습니다** — 실제 번호로 오인될 수 없게

```bash
# 실제 값을 sample.ts 에 채운 뒤
NEXT_PUBLIC_SAMPLE_CONTENT=off   # .env.local 에 추가하면 배너가 사라집니다
```

> ⚠️ **배너가 뜬 상태로 운영 배포하지 마세요.**

### 임시값인 항목

| 항목 | 지금 화면에 | 고칠 곳 |
| --- | --- | --- |
| 사업자등록번호 | `000-00-00000` | `src/lib/sample.ts` |
| 대표자 | 「확인 필요」 | 같음 |
| 통신판매업 신고번호 · 팩스 | `제0000-경주-0000호` / `054-000-0000` | 같음 |
| 운영 시간 | 평일 08:00–18:00 등 | 같음 |
| 장애인 표준사업장 인증번호 · 인증일 | `제0000호` / `0000.00.00.` | 같음 |
| 처리 능력 (일 물량 · 설비 · 차량) | `0,000장` `0대` | 같음 |
| 서비스 권역 | 경주 + 포항 · 울산 북구 · 영천 | 같음 |
| 표준 단가표 | 「예시 초안」 경고와 함께 노출 | `src/lib/pricing.ts` |

단가의 출처는 `Document/품목-단가표.md` 이고, **그 문서 자체가 「예시 초안 — 실제
단가로 수정 필요」라고 명시**하고 있습니다. 그래서 표 위에 그 사실을 항상 함께
표시합니다. 실제 단가가 정해지면 숫자를 바꾸고 `isDraft` 를 `false` 로 내리세요.

### 임시값이 **아닌** 것 (실제 확인된 값)

- 상호 · 주소 · 대표전화 · 장애인 표준사업장 여부 — 전단지 3종에서 확인
- 취급 품목 목록 — `품목-단가표.md`
- 모회사 본사 주소 (경주시 용강동 승삼신리길 80) — jiseong.co.kr 푸터에서 확인
- 자주 묻는 질문 12개의 답 — 확정된 공정 · 운영 방식에서 작성

### 채우지 않은 것

거래처명 · 후기 · 실적 수치는 지어내지 않았습니다. 사업자번호와 달리 이것들은
**실제로 존재하는 것처럼 읽히고 검증도 어려워서**, 더미로 넣으면 그대로 영업 자료가
됩니다. 실제 거래처 동의를 받은 뒤에 넣으세요.

### 사진

실사 촬영 전까지 브랜드 색 **일러스트**(`src/components/illustration.tsx`)로 채웠습니다.
스톡 사진을 쓰지 않은 이유는 이 사이트의 논거가 「실체 있는 업체」라서 남의 공장
사진을 올리면 그 논거를 스스로 무너뜨리기 때문입니다. 그림은 그림으로 보이는 편이
정직하고, 캡션에 「일러스트 · 실사 촬영 후 교체」를 계속 남겨 두었습니다.
