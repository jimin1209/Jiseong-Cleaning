# 지성크리닝 완성 과제 (정효준용) — 이걸 다 끝내면 앱이 완성됩니다

> ⚑ **우리는 도매(B2B)입니다.** 개인 손님이 아니라 **업체(거래처)** 세탁물만 대량으로 수거·세탁·납품합니다.
> (예: 호텔·모텔 침구/수건, 식당 앞치마/행주, 헬스장 수건/가운) → 이 문서의 "고객"은 전부 **거래처(업체)**, "배송"은 **납품**입니다.
>
> 목표: 이 문서의 과제를 **순서대로 전부 완료하면, 명세서 7.1에 정의된 "지성크리닝 MVP 앱"(도매 기준)이 실제로 동작**합니다.
> 방식: 코딩을 몰라도 됩니다. **Codex에게 시키고(지시) → 눈으로 확인(검증) → git 저장(안전)** 을 반복합니다.
> - 개념이 헷갈리면 → `정효준-개발이해-교육가이드.md`
> - Codex 쓰는 법 → `codex-사용-교육매뉴얼.md`
> - 무엇을 만들지 → `명세서.md`(B2B 개정판) / 어떻게 → `개발 설계서.md`(B2B 개정판)
> - 무엇이 확정됐는지 → `결정사항.md` (충돌 시 이 문서가 우선)

## 📖 이 문서 보는 법 (중요)

각 작업은 아래 3줄 형식으로 적혀 있습니다. **그대로 따라 하면 됩니다.**

- [ ] **작업 이름** — 무엇을 만드는지 한 줄 설명 `(명세서 근거)`
  - 🗣 **시킬 말**: Codex 대화창에 붙여넣을 지시(요약형). 앞에 `Document/명세서.md 의 ○.○ 를 읽어줘`를 붙이면 더 정확합니다.
  - ✅ **되면 통과**: 실행해서 이게 눈으로 보이면 그 작업은 끝난 것.

> 체크박스 `[ ]`는 "Codex로 만들고 **실행해서 눈으로 확인**했다"는 뜻. 확인 전엔 체크하지 마세요.
> 한 작업 = 한 번의 지시. 되면 다음으로. **몰아서 시키지 않기.**

## 🎯 "완성"의 정의 (= 목표 앱)

**최종 체크리스트(맨 아래 ✅ 섹션)가 전부 체크되면 앱 완성**입니다. 큰 그림(도매):

```
[거래처] 계정 로그인 → 수거·납품지 등록 → 업소용 품목·수량 대량 발주 → 예상금액 확인 → 발주
        → 검수 후 최종금액 승인 → 정산 → 상태 확인 → 완료·거래명세·문의
[관리자 웹] 발주 접수·관리 → 검수·금액확정 → 배차 → 세탁관리 → 정산·세금계산서 → 거래처·품목·단가·통계
[관리자 모바일] 배정 확인 → 수거·납품 상태변경 → 검수 사진 → 납품 증빙
      ── 셋 다 하나의 서버·DB를 공유 (한쪽에서 바꾸면 모두 반영) ──
```

이 문서는 위를 **6개 단계(Phase)**로 나눕니다. 각 Phase = **① 학습 → ② 세부 작업(시킬 말+통과) → ③ ⭐실전 예시 → ④ 완료 기준**.

## 📋 매 과제 공통 규칙

1. **작업 전 저장**: `지금 상태를 git으로 저장해줘` (--yolo의 안전벨트)
2. **하나씩**: 작업 하나 = 지시 하나. 되면 다음. 몰아서 X.
3. **눈으로 확인**: `실행해서 브라우저에서 보게 해줘`
4. **문서를 가리켜라**: `Document/명세서.md 의 4.9 를 읽고 만들어줘`
5. **막히면 통째 복붙**: 에러/이상화면 전체 복사 → `이거 고쳐줘`
6. **원칙 고정**: 금액은 **서버 계산**(계약단가×수량). 결제·인증·문자는 처음엔 **가짜**. 개인 회원가입 화면은 안 만든다.

## 🧰 기능 하나를 만드는 표준 4단계 (모든 작업에 적용)

**1단계 — 4조각으로 쪼갠다** (가이드 D부):

| 조각 | 자문 |
| --- | --- |
| 🖥 화면 | 어떤 화면에 무슨 버튼·입력칸·목록? |
| 🗄 데이터 | 무엇을 저장/표시? (글자/숫자/날짜/사진) |
| ⚙ 동작 | 버튼 누르면 무슨 일? |
| ⚠ 예외 | 잘못되면 어떻게 안내? |

**2단계 — 4조각을 지시문으로**:
```
Document/명세서.md 의 (번호) 를 읽어줘. 우리는 도매(B2B)라 "고객"은 "거래처"야.
(누가) 가 (어느 화면) 에서 (무엇) 을 하게 만들어줘.
- 화면: (버튼/입력칸/목록)
- 데이터: (저장·표시 항목)
- 동작: (버튼 누르면 일어날 일)
- 예외: (잘못됐을 때 안내)
금액은 서버에서 거래처 계약단가로 계산해줘. 다 되면 실행해서 보게 하고 한국어로 설명해줘.
```

**3단계 — 확인 3종**: ① `실행해서 브라우저에서 보게 해줘. 주소 알려줘.` ② `/diff`(바뀐 것) ③ `방금 만든 걸 쉽게 요약해줘.`

**4단계 — 저장**: `git으로 저장해줘. 메시지는 "○○".`

### ⭐ 실전 예시 — "관리자 품목·단가 등록" (명세서 4.9)

**화면 스케치:**
```
┌ 품목 관리 ─────────────────────────────┐
│ 품목명 [호텔 시트    ] 분류 [침구 ▾]      │
│ 표준단가 [ 800 ] 원    노출 [●켬 ○끔]     │
│                         [ 저장 ]          │
├───────────────────────────────────────┤
│ 품목명    분류   표준단가  노출  [수정][이력]│
│ 호텔 시트  침구    800원  켬               │
│ 대형 수건  수건    600원  켬               │
└───────────────────────────────────────┘
```

**4조각:** 화면=위 스케치 / 데이터=품목명·분류·단가(정수)·노출 / 동작=저장 시 표에 추가, 단가변경 시 이력 / 예외=단가 숫자 아니면 막기

**복붙 지시문:**
```
Document/명세서.md 의 4.9 '품목 및 단가 관리'를 읽어줘. 도매(B2B)야.
관리자 웹 '품목 관리' 화면을 만들어줘.
- 화면: 품목명·분류·표준단가·노출여부 입력칸 + [저장] + 아래 등록 품목 표
- 데이터: 표준단가는 정수(원). 단가를 바꾸면 이전값·바꾼 시각을 이력으로 남겨줘
- 동작: 저장하면 표에 바로 보이고, 노출을 끄면 거래처 발주 화면엔 안 보이게
- 예외: 단가에 숫자 아닌 값이면 "단가는 숫자로 입력하세요", 품목명 비면 저장 못 하게
다 되면 실행해서 품목 두 개를 직접 등록하게 하고 한국어로 설명해줘.
```
**되면 통과:** 시트/침구/800 저장 → 표에 즉시 등장 · 단가 800→900 시 이력 쌓임 · `abc` 입력 시 안내+저장차단
**안 될 때:** `저장한 품목이 표에 바로 안 보여. 저장 후 목록을 새로고침해서 방금 등록한 게 보이게 고쳐줘.`

- [ ] **세탁 발주** — 업소용 품목·수량(대량)·옵션·요청사항·사진 `(3.3)` ★핵심
  - 🗣 `거래처 발주 화면: 품목 목록 + 수량 +/-와 직접입력(대량) + 옵션 + 요청사항 + 사진첨부. (아래 ⭐예시)`
  - ✅ 시트 120·수건 200을 담고 옵션·요청사항까지 넣을 수 있다
- [ ] **예상 금액(서버)** — 계약단가×수량 + 최소물량·수거납품비·할인 구분 `(3.3)` ★핵심
  - 🗣 `예상금액 = 이 거래처 계약단가 × 수량 합. 반드시 서버 계산. 최소 발주금액·수거납품비·할인을 구분해서 보여줘.`
  - ✅ 수량 바꾸면 금액 자동 갱신, 화면에서 금액 조작해도 저장값은 서버 계산값
- [ ] **일정 선택** — 수거·납품 희망일/시간대(마감 시간대 선택불가) `(3.3, 4.10)`
  - 🗣 `수거·납품 희망 날짜·시간대를 고르게 하고, 이미 마감된(최대물량 찬) 시간대는 못 고르게 해줘.`

  - ✅ 확인 화면을 거쳐 발주하면 발주번호가 나온다
- [ ] **거래처 발주 조회** — 진행중/과거 구분, 상세 `(3.6)`

  - ✅ 진행중·과거 탭이 나뉘고 상세가 보인다
- [ ] **발주 변경·취소 요청** — 허용 시점까지 `(3.7)`

  - ✅ 수거 전엔 취소, 수거 후엔 '취소 요청'으로 바뀐다
- [ ] **관리자 발주 관리** — 목록·검색·필터, 접수·거절, 수정 `(4.3)`

  - 🗣 `발주 상태를 명세서 5장 순서로 진행하고, 취소·거절 같은 예외 상태도 두고, 모든 변경에 이력을 남겨줘.`
  - ✅ 상태가 순서대로 넘어가고 예외도 처리되며 이력이 쌓인다
- [ ] **중복 발주 방지** — 같은 발주 두 번 방지 `(6.2)`
  - 🗣 `[발주하기]를 빨리 두 번 눌러도 발주가 하나만 저장되게 해줘.`
  - ✅ 두 번 눌러도 발주는 한 건만 생긴다

### ⭐ 실전 예시 — "거래처 세탁 발주 + 예상금액(서버계산)" (명세서 3.3) ★가장 중요★

**화면 스케치:**
```
┌ 세탁 발주 ─ 사업장: [행복호텔 본점 ▾] ──────┐
│ 품목            단가      수량             │
│ 호텔 시트        800원   [－] 120 [＋]     │
│ 대형 수건        600원   [－] 200 [＋]     │
│ 목욕 가운      1,500원   [－]   0 [＋]     │
│ 요청사항 [ 얼룩 심함, 개별포장          ]  │
│ 사진 [＋첨부]   수거희망 [9/1 오전 ▾]      │
├───────────────────────────────────────┤
│ 예상금액(서버계산)          216,000원      │

└───────────────────────────────────────┘
```

**복붙 지시문:**
```
Document/명세서.md 의 3.3 '세탁 발주'를 읽어줘. 도매(B2B)라 거래처가 업소용 품목을 대량 발주해.
거래처 발주 화면을 만들어줘.
- 화면: 등록 품목 목록 + 각 품목 수량을 +/-와 직접입력(대량)으로, 하단에 예상금액 자동 표시 + [발주하기]
- 데이터: 예상금액 = 이 거래처 계약단가 × 수량 합. 반드시 서버에서 계산(화면 값 신뢰 금지)
- 동작: 수량 바꾸면 예상금액 자동 재계산, [발주하기] → 발주 저장 + 발주번호(JS-YYYYMMDD-0001)
- 예외: 전체 수량 0이면 발주 불가, 최소 발주금액 미달이면 "최소 5만원 이상 발주 가능" 안내
다 되면 실행해서 호텔 시트 120·수건 200을 직접 발주하게 해줘.
```
**되면 통과:** 시트 100→120 시 금액 자동↑ · [발주하기] 시 발주번호 · 화면 금액 조작해도 저장은 서버값
**안 될 때:** `수량을 바꾸면 예상금액이 서버에서 다시 계산돼 자동 갱신되게 고쳐줘.`

# 💬 복붙용 만능 문장 모음 (코딩 몰라도 이대로만)

**시작·저장**
- `지금 상태를 git으로 저장해줘. 메시지는 "○○".`
- `방금 작업을 취소하고 마지막으로 저장한 상태로 되돌려줘.`

**만들 때**
- `Document/명세서.md 의 ○.○ 를 읽어줘. 우리는 도매(B2B)라 "고객"은 "거래처"야. 그 화면을 만들어줘.`
- `한 번에 다 만들지 말고, ○○ 기능 하나만 먼저 만들고 멈춰서 한국어로 설명해줘.`
- `금액은 화면 값 믿지 말고 서버에서 거래처 계약단가로 계산해줘.`

**확인할 때**
- `방금 만든 걸 실행해서, 내가 브라우저에서 직접 볼 수 있게 해줘. 주소 알려줘.`
- `/diff` (바뀐 파일 보기) · `방금 한 작업을 코딩 모르는 사람도 알게 항목별로 요약해줘.`

**막혔을 때**
- `(빨간 에러 전체를 붙여넣고) 이 에러가 났어. 무슨 뜻이고 어떻게 고쳐?`
- `(이상한 화면을 설명하고) 이 화면이 이렇게 나와야 하는데 저렇게 나와. 고쳐줘.`

> **한 줄 요약:** 우리는 도매(B2B). 매 작업을 **4조각으로 쪼개 → 시킬 말 붙이고 → '되면 통과'로 확인 → 저장**.
> Phase 0로 심장을 뛰게 하고 Phase 1~5로 살을 붙이면, **최종 체크리스트가 전부 ✅면 앱 완성**입니다.
