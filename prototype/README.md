# 회의용 서비스 목업

**사장님 보고 → 설계 방향 확정**이 목적이다. 코드 착수 전에 이걸 먼저 보여준다.

## 여는 법

```
prototype/index.html 을 브라우저로 열면 끝 (빌드·서버·인터넷 불필요)
```

**파일 하나로 완결된다.** 외부에서 불러오는 스크립트·폰트·이미지가 없어서
카톡이나 메일로 이 파일만 보내도 상대방 PC에서 그대로 열린다.

## 담긴 것

| 역할 | 화면 |
|---|---|
| 고객 | 홈 · 수거 신청 · 신청 확인 · 주문 추적 · **추가금 승인** · 구독 |
| 기사 | 오늘의 배차 · 수거 완료 |
| 세탁공장 | 작업 보드 · **검수 입력** |
| 관리자 | 대시보드 · 배차 보드 · **요금표 설정** · **배상 기준** |

굵은 표시 = 회의에서 반드시 짚어야 하는 화면.

요금·지역·구독 데이터는 `seed/` 초안을 그대로 썼다. 화면에서 보이는 숫자가 곧 시드 값이다.

## 회의 진행

- 좌측 목록 = 실제 서비스 흐름 순서. 위에서 아래로 따라가면 서비스 한 바퀴다.
- 좌측 목록의 주황 점 = 결정 항목이 있는 화면.
- `←` `→` 키로 화면 이동. 우상단에서 결정 패널을 접거나 다크 모드로 바꿀 수 있다.

### 회원 유형 전환 (고객 화면)

상단의 **일반(건별) / 구독** 스위치로 두 경우를 비교한다.
**구독은 선택 사항이고, 가입하지 않아도 건별로 그대로 이용할 수 있다.** 건별 고객 화면에는
구독 차감 줄이 없고 전액을 결제한다.

## 결정 수집 — 결과를 회신받기

이 목업은 **보기만 하는 물건이 아니라 결정을 받아오는 도구**다.

```
사장님: 화면 보면서 우측 패널에서 선택 (필요하면 메모)
        → 우상단 "결과 보기" → 아래 셋 중 하나로 회신
담당자: 받은 것을 목업의 "받은 결과 열기"에 붙여넣으면 그대로 복원
```

| 회신 방법 | 쓰는 상황 |
|---|---|
| **① 결과 코드** | 파일로 주고받을 때. 짧은 문자열이라 카톡에 그대로 붙여넣으면 된다 |
| **② 요약 글** | 읽을 수 있는 문장. 회신 겸 보고용으로 바로 쓸 수 있다 |
| **③ 링크** | 웹에 올려둔 경우에만. 파일로 열면 자동으로 숨겨진다 |

- 결정 **15개**. 진행률이 우상단에 계속 표시된다.
- 서버도 로그인도 없다. 답은 코드/링크 안에 인코딩된다.
- 브라우저에 자동 저장되므로 창을 닫았다 열어도 남아 있다.
- **`.md` 요약 파일** 저장 가능 — 보고서에 그대로 붙이면 된다.
- 결과에 **제안대로 / 제안과 다름**이 표시되어, 기본 설계에서 무엇이 바뀌는지 바로 보인다.

## 배포

원격 참석자와 공유하려면 URL이 필요하다. **[배포방법.md](배포방법.md)** 참조 — Netlify에
`deploy` 폴더를 드래그하면 끝난다.

```
https://<발급받은주소>.netlify.app/nv39h7gq3j7pf6/
```

경로에 무작위 문자열을 넣어 주소를 모르면 찾을 수 없게 했다.
외부 리소스를 전혀 안 쓰므로 어디에 올려도 그대로 동작한다.

목업을 고쳤으면 `deploy/` 안의 파일을 갱신한 뒤 다시 드래그한다.

## 이 목업의 한계

- **동작하지 않는다.** 목업 화면의 버튼은 눌러도 반응 없고, 화면 이동은 좌측 목록으로만 한다.
  (결정 패널·결과 화면은 실제로 동작한다)
- 데이터는 전부 고정값이다.
- 화면에 있는 금액은 요금표 초안 기준이며 실제 청구 로직을 거친 값이 아니다.
- 목적이 "이 방향이 맞는가"를 정하는 것이라, 예외 화면(오류·빈 상태·로딩)은 넣지 않았다.
- 링크에 답이 들어가므로 **링크를 받은 사람은 답을 볼 수 있다.** 민감한 내용은 메모에 적지 않는다.

## 회의 후

확정된 결정을 `seed/*.json` 과 문서 09·13에 반영한 뒤 Phase 0(모노레포 스캐폴딩)에 착수한다.
방향이 크게 바뀌면 목업을 먼저 고치고 다시 확인받는 게 코드를 고치는 것보다 싸다.
