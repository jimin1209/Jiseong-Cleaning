# 13. 운영 설정 — 관리자 인터페이스

> **개발자 없이 사장이 직접 바꿀 수 있어야 하는 것 전부.**
> 세탁 사업을 하면서 내리는 결정 중 코드에 박아두면 안 되는 것들을 모아 설계했다.
> 판단 기준은 하나다 — **"이걸 바꾸려고 개발자를 불러야 하나?"** 그렇다면 설정으로 뺀다.

---

## 0. 설계 원칙

| 원칙 | 내용 |
|---|---|
| **하드코딩 금지** | 숫자·기간·비율·문구는 전부 설정. 코드에는 **기본값만** |
| **설정 레지스트리** | 설정 하나 추가할 때 화면을 새로 만들지 않는다. 레지스트리에 항목을 등록하면 화면이 자동 생성 (§16.2) |
| **미리보기 → 적용** | 즉시 저장 없음. 무엇이 바뀌는지 보여주고 확인받는다 |
| **영향도 표시** | "이 값을 바꾸면 무엇이 어떻게 되는지"를 숫자나 문장으로 |
| **사유 필수 + 이력** | 모든 변경은 `audit_logs`. 되돌리기 가능 |
| **권한 분리** | 돈·법적 사항은 `SUPER_ADMIN`, 일상 운영값은 `STAFF`도 가능 |
| **위험 표시** | 잘못 만지면 사고 나는 항목에는 🔴 표시 + 2차 확인 |

**조작**
- 금액 칸 인라인 편집. 변경된 행은 **노란 배경 + ▲/▼**
- 여러 개 고쳐도 **저장 전까지 아무것도 반영되지 않는다**
- 저장 안 하고 이탈 시 확인 팝업

> "월 매출 +30만원, 구독 초과 발생률 +4%p"는 판단할 수 있다.

### 2.3 일괄 수정

| 기능 | 동작 |
|---|---|
| **엑셀 내보내기** | 현재 요금표 `.xlsx` 다운로드 |
| **엑셀 가져오기** | 업로드 → **차이만 추출**해 변경 목록으로 표시 → 미리보기 → 적용 |
| **일괄 조정** | 선택 품목/카테고리에 `+N원` 또는 `+N%` |
| **반올림** | % 조정 시 100원 단위 올림 (2,000 × 1.07 = 2,140 → **2,200**) |

> 엑셀 가져오기는 **덮어쓰기가 아니라 차이 추출**이다. 파일 전체를 그대로 반영하면
> 그사이 다른 사람이 바꾼 값까지 되돌려버린다.

### 2.4 ⭐ 가격 변경이 주문에 미치는 영향

| 상황 | 적용 가격 |
|---|---|
| 이미 접수된 주문 | **접수 시점 가격** (`order_items.unit_price_snapshot`) |
| **검수 중 공장이 추가한 품목** | **그 주문 접수일 기준 유효가** ← 오늘 가격이 아니다 |
| 신규 주문 | 접수 시점의 현재가 |

```
getPriceAt(serviceItemId, date)
  → service_item_prices 에서 effective_from <= date 중 최신
```

> 8월에 신청한 고객이 9월 인상가로 청구받으면 분쟁이다.

### 2.5 검증 규칙

| 규칙 | 처리 |
|---|---|
| 단가 0원 이하 | 🔴 차단 |
| **변동폭 ±30% 초과** | ⚠️ "기존 대비 45% 인상입니다" 2차 확인 |
| 단가 100만원 초과 | ⚠️ 경고 후 진행 가능 |
| 소요일 0 또는 30 초과 | 🔴 차단 |
| 코드 중복 | 🔴 차단 |
| 활성 품목 비활성화 | ⚠️ "진행 중 주문 3건에 포함" (진행 가능 — 기존 주문은 스냅샷) |

### 3.3 ⭐ 기존 구독자 보호 (grandfathering)

**이게 없으면 사고가 난다.** 관리자가 가격을 고쳤을 뿐인데 다음 날 68명이 모르는
금액으로 자동결제되면 그건 사전 고지 없는 요금 인상이다.

**해결: 가입 시점 조건을 `subscriptions`에 스냅샷으로 박는다.**

| 상황 | 동작 |
|---|---|
| 가격 변경 (신규만) | `subscription_plans` 갱신. 기존 구독자 스냅샷은 **그대로** |
| 기존에도 적용 | 30일 후 적용 예약 → 배치가 스냅샷 갱신 |
| 사전 고지 | 예약 시 대상자 전원에게 **알림톡 자동 발송** |
| 플랜 비활성화 | **신규 가입만 차단.** 기존 구독자 유지 (강제 해지 금지) |
| 플랜 삭제 | **불가.** 비활성화만 |

> ⚠️ 고지 기간·방법은 약관에 명시하고 실제 기간은 **법률 자문으로 확인**할 것. 위 30일은 관행값이다.

### 3.4 검증

| 규칙 | 처리 |
|---|---|
| **회당 한도 × 포함 횟수 > 월 요금 × 2** | 🔴 "역마진 위험: 한도를 다 쓰면 월 X원 손실" |

## 9. ⭐ 배상 기준 — 세탁업에서 가장 중요한 설정

세탁물 분실·손상은 **반드시 발생한다.** 그때마다 사장이 감으로 정하면
고객마다 금액이 달라지고, 그게 분쟁의 씨앗이 된다. **표로 미리 정해둔다.**

```

├────────────────────────────────────────────────────────────────────┤

│  ○ 건별 협의                                                       │
├────────────────────────────────────────────────────────────────────┤
│ 배상비율표 — 품목군별 내용연수와 사용일수 구간                      │
│                                                                    │
│  품목군          내용연수   사용 20%↓  20~40%  40~60%  60~80%  80%↑ │
```

### 16.2 ⭐ 설정 레지스트리 — 화면을 매번 만들지 않는 방법

설정 항목이 37개인데 각각 화면을 만들면 유지가 안 된다.
**코드에 스키마를 선언하면 관리자 화면이 자동 생성**되게 한다.

```ts
// packages/shared/src/settings/registry.ts
export const SETTINGS = {
  'order.cutoff_time': {
    category: 'ORDER',
    label: '당일 신청 마감 시각',
    description: '수거 전날 이 시각까지 신청분만 다음 날 수거 가능',
    type: 'time',
    default: '22:00',
    role: 'STAFF',
  },
  'inspection.approval_threshold_rate': {
    category: 'INSPECTION',
    label: '추가금 승인 임계 비율',
    description: '확정 금액이 예상의 이 비율을 넘으면 고객 승인 필요',
    type: 'number', unit: '%', min: 100, max: 200,
    default: 110,
    role: 'SUPER_ADMIN',
    danger: true,                 // 🔴 표시 + 2차 확인
    simulate: 'approvalRate',     // 시뮬레이션 함수 연결 (§7.1)
  },
  'switch.new_orders_enabled': {
    category: 'SWITCH',
    label: '신규 주문 접수',
    type: 'boolean', default: true,
    role: 'SUPER_ADMIN', danger: true,
    immediate: true,              // 예약 적용 없이 즉시
  },
  // ... 37개
} as const
```

| 얻는 것 | 설명 |
|---|---|
| 화면 자동 생성 | 카테고리별로 폼이 자동 구성. 설정 추가 = 레지스트리 한 줄 |
| 검증 일원화 | `min`/`max`/`type`을 프론트·백엔드가 함께 사용 |
| 타입 안전 | `getSetting('order.cutoff_time')` 이 `string`으로 추론됨 |
| 기본값 보장 | DB에 값이 없으면 `default` 사용 → 마이그레이션 부담 없음 |
| 권한·위험도 | `role`, `danger` 로 접근·확인 절차 자동 처리 |

### Phase 1에 반드시 들어가야 하는 것
**설정 레지스트리 · 요금표 · 슬롯 · 지역 · 회사정보** 5개.
나머지는 기본값으로 두고 나중에 화면을 붙여도 된다.

### 나중에 넣으면 안 되는 것 (돌이킬 수 없음)
- **구독 스냅샷 (§3.3)** — 나중에 넣으면 기존 구독자의 원래 조건을 복원할 방법이 없다
- **가격 이력 (§2.4)** — 나중에 넣으면 과거 시점 가격을 알 수 없다
- **약관 동의 버전 기록** — 나중에 넣으면 누가 무엇에 동의했는지 증명할 수 없다
