# 09. 마스터 데이터 초안 (수정용)

> **이 문서의 모든 숫자는 "일단 채워둔 초안"이다.** 타사(런드리고·세탁특공대·크린토피아 등)
> 공개 요금과 일반적인 세탁 시세를 참고해 만들었고, 실제 원가·경주 지역 시세에 맞춰
> **그대로 고쳐 쓰면 된다.** 코드에 하드코딩하지 않고 전부 DB 시드 → 관리자 화면에서 수정 가능.
>
> 확정된 전제: **① 서비스 지역 = 경주 전지역** · **④ 세탁공장 = 자사 시설**

## 1. 서비스 지역 — 경주시 전역 (23개 읍면동)

### 1.1 ⚠️ 먼저 짚어야 할 문제

경주시는 **면적 1,324km²로 서울의 2.2배**다. 시내(중부동)에서 산내면·양남면까지 편도 40km가 넘는다.
"경주 전지역"을 **모든 지역 매일 수거·배송**으로 운영하면 기사 1명이 하루에 산내면 1건 때문에
80km를 왕복하는 상황이 생긴다. 그래서 **전지역 서비스는 유지하되 권역별 운영일을 나눈다.**

### 1.2 권역 구분 (초안)

| 권역 | 지역 | 시내 기준 거리 | 운영일 | 최소 주문금액 |
|---|---|---|---|---|
| **1권역**<br>시내 | 중부동, 황오동, 성건동, 황남동, 월성동, 선도동, 용강동, 황성동, 동천동, 불국동, 보덕동 (11동) | ~10km | **매일** | 15,000원 |
| **2권역**<br>근교 | 현곡면, 천북면, 건천읍, 내남면, 외동읍 | 5~15km | **월·수·금** | 20,000원 |
| **3권역**<br>외곽 | 안강읍, 강동면, 서면, 감포읍, 문무대왕면, 양남면, 산내면 | 20~40km | **화·목** | 25,000원 |

> 최소 주문금액 미달 시 수거·배송비 3,000원 별도 청구 (또는 신청 차단 — 정책 선택)

**운영 규칙**
- 각 권역 운영일에만 해당 지역 시간 슬롯이 열린다 (`time_slots.weekdays` ∩ `service_areas.operating_days` − 휴무일)
- 초기 물량이 적으면 2·3권역은 **주 1회로 더 줄여도** 된다 (운영해 보고 조정)

**⚠️ 배송일 계산이 단순 덧셈으로 안 되는 케이스**

3권역(화·목 운영)에서 **화요일에 이불(소요일 4일)을 수거**하면,
`수거일 + 4일 = 토요일`인데 **토요일은 3권역 운영일이 아니다.** 그다음 운영일인
**다음 주 화요일**이 실제 배송 가능일이 된다. 즉 고객 체감 소요는 4일이 아니라 7일이다.

```
배송가능일 = MIN{ d | d ≥ 수거일 + lead_time_days + zone_lead_days
                   AND d ∈ service_areas.operating_days
                   AND d ∉ holidays }
```
- 주문 여러 품목이 섞이면 **가장 긴 `lead_time_days`** 기준으로 잡는다
- 이 계산 결과를 **주문 신청 화면(C-05 STEP 4)에 "예상 배송 8/18(화)"로 미리 보여줘야 한다.**
  안 보여주면 "왜 일주일이나 걸리냐"는 CS가 3권역에서 반드시 발생한다
- 구현 위치: `catalog` 모듈의 `estimateDeliveryDate(areaCode, pickupDate, items)`

| 항목 | 초안 | 이유 |
|---|---|---|
| 미사용 횟수 이월 | **없음** | 이월을 허용하면 정산·환불 계산이 급격히 복잡해진다 |
| 중도 해지 | **기간 말 해지** (일할 환불 없음) | 업계 표준, 계산 단순 |
| 플랜 변경 | **다음 결제주기부터 적용** | 비례배분(proration) 로직 불필요 |
| 첫 달 프로모션 | 첫 달 50% | 초기 고객 확보용, 1회만 |
| 결제 실패 | 1일 간격 3회 재시도 → PAUSED | 문서 06 §4.2 |
| 최소 유지기간 | 없음 | 약정은 이탈률만 높인다 |

> **손익 감각 체크:** 스탠다드 39,900원 / 월 4회 / 회당 15,000원 커버 = 최대 60,000원어치 제공.
> 고객이 매번 한도를 꽉 채워 쓰면 **역마진**이다. 실제로는 평균 사용액이 한도의 60~70% 수준이라
> 유지되는 구조인데, 오픈 후 3개월 데이터로 **반드시 재조정**해야 한다.
> 초기엔 회당 한도를 좀 더 보수적으로(12,000원 정도) 잡는 것도 방법이다.

## 4. 시간 슬롯 초안 (`time_slots`)

> ⚠️ **정원은 기사 처리량에서 역산해야 한다.** 슬롯 정원을 기사 용량보다 크게 잡으면
> 주문은 받아놓고 못 가는 상황이 생긴다. 기사 1명 = **하루 25건(수거+배송 합산)** 이 상한이다.
> (§6.2 산정 근거) PICKUP·DELIVERY가 별도 행이므로 **같은 시간대 두 정원의 합**으로 계산한다.

### 오픈 초기 (기사 1명 = 하루 25건) — 슬롯 2개만 운영
| 시간대 | PICKUP 정원 | DELIVERY 정원 | 시간대 합계 |
|---|---|---|---|
| 10:00 ~ 13:00 | 5 | 5 | 10건 |
| 18:00 ~ 21:00 | 8 | 7 | **15건** |
| | | | **합 25건 = 기사 용량과 일치** |

> **저녁 슬롯(18-21시)에 정원을 더 준다.** 직장인은 낮에 집에 없어서 저녁에 신청이 몰린다.

### 확장 후 (기사 2명 = 하루 60건)
| 시간대 | PICKUP | DELIVERY | 합계 |
|---|---|---|---|
| 09:00 ~ 12:00 | 8 | 7 | 15 |
| 12:00 ~ 15:00 | 8 | 7 | 15 |
| 15:00 ~ 18:00 | 8 | 7 | 15 |
| 18:00 ~ 21:00 | 8 | 7 | 15 |
| | | | **합 60건 ≤ 2명 × 30** |

**휴무일:** 일요일 + 법정공휴일 + 설·추석 연휴 (관리자 화면에서 등록)

## 5. 세탁공장 (자사 시설) — `factory_profiles`

```
factory_name    : 지성클리닝 세탁센터
is_internal     : true          ← 자사 시설 확정
address         : (경주시 내, 위치 확정 필요)
capacity_per_day: 120           ← 일 처리 가능 주문 건수 (초안)
```

### 5.1 자사 시설이라서 달라지는 점 (설계 반영 사항)

| 항목 | 외주였다면 | **자사이므로** |
|---|---|---|
| 공장 정산 | 정산 로직·월별 마감 필요 | **불필요** → 개발 범위에서 제외 |
| 원가 관리 | 외주 단가가 원가 | 인건비·수도광열비·소모품이 원가 → 회계로 관리, 앱 밖 |
| 검수 신뢰도 | 외주 검수를 검증할 장치 필요 | 내부 직원이라 상대적으로 단순 |
| 손상 책임 | 외주와 책임 소재 다툼 | **전부 자사 책임** → 검수 사진이 더 중요해짐 |
| 계정 | 업체별 계정 분리 | **공장 계정 1개**로 충분 (초기) |

> ✅ **문서 01의 "공장 정산" 항목을 개발 범위에서 삭제한다.** (2차에도 불필요)
> ⚠️ 대신 **손상·분실 책임을 전부 우리가 진다.** 검수 사진 필수화와 영업배상책임보험이 더 중요해졌다.

### 5.2 공장 인력 초안
| 역할 | 인원 | 담당 |
|---|---|---|
| 검수 담당 | 1명 | 입고 스캔 · 품목 확정 · 특이사항 촬영 (앱 사용) |
| 세탁 담당 | 2명 | 물세탁 / 드라이 |
| 포장·출고 | 1명 (검수 겸임 가능) | 포장 · 출고 스캔 |

> **앱을 실제로 쓰는 사람은 검수 담당 1명**이다. 이 사람이 하루에 100건씩 입력해야 하므로
> F-04 검수 화면의 입력 속도가 서비스 전체의 병목이 된다. 단축키·숫자패드·바코드를 최대한 활용할 것.

### 5.3 처리 능력
```
일 처리 목표 120건 × 평균 6점 = 720점/일
검수 소요: 건당 2~3분 → 120건 = 약 5시간 (1명이 커버 가능)
표준 소요일: 물세탁 2일, 드라이 3~4일, 침구 4~5일, 신발 4~5일
```

## 6. 기사 운영 계획 초안

### 6.1 단계별 인력

| 단계 | 조건 | 기사 | 차량 | 운영 |
|---|---|---|---|---|
| **오픈** | 일 10~25건 | **1명** | 1톤 탑차 or 스타렉스 1대 | 1권역 매일 / 2권역 월수금 / 3권역 화목 |
| 확장 1 | 일 25건 초과 2주 지속 | 2명 | +1대 | 권역 분담 (시내 / 외곽) |
| 확장 2 | 일 60건 초과 | 3~4명 | +2대 | 슬롯 4개 전면 운영 |

### 6.2 기사 1명 처리 능력 산정
```
1건당 소요 = 이동 8분 + 대면/문앞 처리 4분 = 약 12분
슬롯 3시간(180분) ÷ 12분 ≈ 15건
슬롯 2개 운영 → 하루 최대 약 30건 (수거 + 배송 합산)
현실적 목표 = 하루 25건  → driver_profiles.daily_capacity = 25
```
> 단, **3권역(산내·양남·감포)이 섞이면 이동시간이 8분이 아니라 40분**이 된다.
> 그래서 3권역은 운영일을 묶어서 하루에 몰아 도는 구조로 잡은 것이다.

### 6.3 고용 형태 (선택)

| 안 | 조건 | 장단점 |
|---|---|---|
| **A. 직고용 (권장)** | 월 280~320만원 + 차량·유류 회사 부담 | 물량 적은 초기에 비용 고정. 교육·품질 관리 쉬움 |
| B. 위탁 (건당) | 건당 2,500~3,500원 | 물량 많을 때 유리. 초기엔 기사 수입이 적어 이탈 |
| C. 겸업 | 기존 직원이 겸임 | 초기 물량 극소일 때만. 확장 불가 |

> 초기 하루 15건 × 3,000원 = 45,000원/일 = 월 117만원. **위탁 기사가 못 버틴다.**
> 물량이 궤도에 오르기 전까지는 **A안(직고용)** 이 맞다.

### 6.4 기사 배정 초안 (`driver_profiles`)
```
기사1 (오픈 시)
  service_area_codes : 경주 전지역 23개 전부
  daily_capacity     : 25
  vehicle_no         : (확정 필요)

기사2 (확장 1 시점)
  기사1 : 1권역 11개 동 (시내 전담)
  기사2 : 2·3권역 12개 읍면 (외곽 전담)
```

## 7. 수정 시 참고

| 이 값을 바꾸면 | 영향받는 곳 |
|---|---|
| 품목 단가 | `service_items` 시드만 수정. 기존 주문은 스냅샷이라 영향 없음 |
| 구독 회당 한도 | 손익에 직결. 문서 06 §2 계산 예시도 같이 확인 |
| 권역 구분 | `service_areas.zone` + 시간 슬롯 운영일 + 기사 배정 |
| 슬롯 정원 | `time_slots.capacity`. 기사 수 × 15 를 넘기지 말 것 |
| 기사 수 | `driver_profiles.daily_capacity` 총합이 일 주문량을 커버하는지 |

**시드 파일:** 이 문서의 내용은 `지성클리닝\seed\` 에 JSON으로 이미 만들어 뒀다.
구현 시 `apps/api/prisma/seed/` 로 복사해서 쓰면 된다.
```
seed/
├─ service-areas.json      # §1.3  경주 23개 읍면동 + 권역 + 운영요일
├─ service-items.json      # §2    품목 46종
├─ subscription-plans.json # §3    구독 플랜 4종
├─ time-slots.json         # §4    시간 슬롯 (확장용은 isActive:false)
└─ accounts.json           # 관리자·공장·기사 초기 계정
```

### 시드에 넣지 못한 항목 (별도 처리 필요)

| 항목 | 이유 | 처리 방법 |
|---|---|---|
| `RUSH` 긴급 할증 (주문금액 30%) | **정률**이라 `unit_price`(정액) 컬럼으로 표현 불가 | 별도 `order_options` 테이블을 두거나, `service_items`에 `rate` 컬럼 추가. 구현 시 결정 |
| `WNF_EXTRA` 초과 kg | 기본 12kg를 넘긴 만큼만 과금 | 검수 시 공장이 초과 kg를 입력 → `qty_confirmed`에 초과분만 기입 |
| 읍면동 행정표준코드 | 정확한 코드를 확인하지 못함 | [code.go.kr](https://www.code.go.kr)에서 경주시(시군구코드 47130) 조회 후 `areaCode` 교체 |
| 공장·기사 실제 정보 | 미확정 | `accounts.json`에 플레이스홀더로 표시해 둠 |
