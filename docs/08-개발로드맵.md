# 08. 개발 로드맵

> 전제: **개발자 1명(최지민) 파트타임** 기준. 본업(K마크 인증, 산불 R&D, 블랙아이스)과 병행이라면
> 아래 일정의 **1.5~2배**로 잡아야 현실적이다. 풀타임 기준 약 12주, 병행 기준 5~6개월.

---

## Phase 0 — 기반 구축 (1주)

| 작업 | 산출물 |
|---|---|
| 모노레포 스캐폴딩 (Turborepo + pnpm) | `apps/web`, `apps/api`, `packages/shared` |
| Docker Compose (Postgres, Redis, MinIO) | 로컬 개발 환경 1커맨드 실행 |
| Prisma 스키마 작성 + 초기 마이그레이션 | 문서 03의 전체 테이블 |
| 시드 데이터 (품목·요금·슬롯·지역·관리자 계정) | `prisma/seed.ts` |
| 공통 응답/에러 포맷, 로깅(Pino+redact), Swagger | |
| GitHub 저장소 + Actions (lint/typecheck/test/build) | ✅ 저장소 생성 완료 |
| **테스트 기반 셋업** (Vitest + Testcontainers + fixtures) | 문서 10 §7 |

**완료 기준:** `docker compose up` → `pnpm dev` 로 web/api가 뜨고 Swagger에서 헬스체크 응답,
`pnpm test` 가 빈 상태로라도 통과

## Phase 1 — 인증 + 고객 주문 + 관리자 관제 (3주)

| 주 | 작업 |
|---|---|
| 1 | 인증 전체 (SMS 인증·JWT·refresh 회전·Guard 3종), 주소 CRUD |
| 2 | 카탈로그 API(품목·지역·견적), **권역별 슬롯 계산 + 배송예정일 계산**(문서 09 §1.2), 고객 주문 생성/조회, **상태머신 서비스** + 낙관적 잠금 |
| 3 | 고객 화면 C-01~C-07, C-09 / 관리자 화면 A-01~A-04, A-10~A-12 |
| 전 주 | **테스트: 상태 전이표 전수(문서 10 §3.1) · 권한(§3.5) · 권역 계산(§3.6)** |

**이 단계의 핵심:** `order-state.service.ts` 를 제대로 만드는 것.
이후 모든 기능이 여기 얹히므로 여기서 대충 하면 뒤에서 전부 다시 짜게 된다.

**완료 기준(데모 가능):**
고객이 가입 → 주소 등록 → 수거 신청 → 관리자가 목록에서 확인하고 상태를 수동으로 끝까지 넘김
→ 고객 화면에서 진행 상황이 보인다.

**⚠️ 이 시점에 PG 계약과 알림톡 발신프로필 신청을 시작한다.** (문서 06 §8)

## Phase 2 — 기사 앱 + 배차 (2주)

| 작업 |
|---|
| 배차 도메인 (`assignments`), 관리자 수동 배차 API |
| 관리자 A-05, A-06 (배차 보드, 드래그 배차) |
| 기사 화면 D-01~D-05 |
| 사진 업로드 (presigned URL, 클라이언트 리사이즈, EXIF 제거) |
| 기사 상태 전환 + 낙관적 잠금 + Idempotency-Key |
| 기사 계정 관리 A-08 |
| **배차표 인쇄 기능** (A-05) — 앱 장애 시 종이 운영용 (문서 12 §0.1) |
| 테스트: 낙관적 잠금(문서 10 §3.8), 슬롯 동시성(§3.7) |

**완료 기준:** 관리자가 배차 → 기사가 폰으로 출발/도착/수거완료(사진) 처리 → 고객 화면에 반영

## Phase 3 — 세탁공장 + 검수/추가금 (2주)

| 작업 |
|---|
| `factory_jobs` 도메인, 입고 QR 스캔 |

**완료 기준:** 수거 → 입고 → 검수(수량 보정) → 고객 승인 → 세탁 → 출고 → 배송 전 과정이 실제로 흐른다.
