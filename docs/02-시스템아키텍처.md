## 4. 인증 · 인가 설계

### 토큰
```
Access Token  : JWT, 15분,  Authorization 헤더 (메모리 보관)
Refresh Token : JWT, 14일,  httpOnly + Secure + SameSite=Lax 쿠키
                → DB에 해시 저장, 회전(rotation) 방식, 재사용 감지 시 전체 무효화
```

JWT payload:
```json
{ "sub": "user_uuid", "role": "DRIVER", "factoryId": null, "jti": "...", "exp": 1234 }
```

### 3중 인가 체크
```
1) JwtAuthGuard      → 토큰 유효한가
2) RolesGuard        → @Roles('ADMIN','DRIVER') 데코레이터로 역할 검사
3) OwnershipGuard    → 이 리소스가 이 사람 것인가
                       · 고객: order.customerId === user.id
                       · 기사: assignment.driverId === user.id
                       · 공장: order.factoryId === user.factoryId
```

> **3번을 빼먹으면 다른 고객 주문번호만 알아도 조회가 뚫린다.** 서비스 레이어에서
> 항상 `where` 절에 소유자 조건을 강제하는 헬퍼를 두고 우회 불가하게 한다.

### 로그인 후 라우팅
```
로그인 성공 → role 확인 → CUSTOMER: /  |  DRIVER: /driver  |
                          FACTORY: /factory  |  ADMIN: /admin
미들웨어(middleware.ts)에서 경로 prefix와 role 불일치 시 403 리다이렉트
```

## 5. PWA 설계

### 설치 · 매니페스트
```json
{
  "name": "지성클리닝",
  "short_name": "지성클리닝",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#ffffff",
  "theme_color": "#0B5FFF",
  "icons": [ /* 192, 512, maskable */ ]
}
```

### 캐시 전략 (Workbox)
| 리소스 | 전략 |
|---|---|
| JS/CSS/폰트 | CacheFirst (버전 해시) |
| 이미지(아이콘/정적) | CacheFirst, 30일 |
| API GET (품목·요금표) | StaleWhileRevalidate |
| API GET (주문 상태) | NetworkFirst, 3초 타임아웃 → 캐시 |
| API POST/PATCH | 캐시 안 함. 기사 상태변경만 2차에서 Background Sync 큐잉 |

### 푸시 알림 — **주의**
| 플랫폼 | 웹푸시 가능 여부 |
|---|---|
| Android Chrome | ✅ 정상 |
| Windows/Mac 데스크톱 | ✅ 정상 |
| **iOS Safari** | ⚠️ **16.4+ 이면서 "홈 화면에 추가" 한 경우에만** 가능 |

→ iOS 사용자가 홈화면 추가를 안 하면 푸시가 아예 안 온다.
→ **카카오 알림톡을 보조가 아니라 주 채널로** 설계한다. (수거/배송 알림은 알림톡 필수)

### 기사용 화면 특수 고려
- 대형 터치 타겟 (최소 48px), 한 손 조작
- 카메라: `<input type="file" accept="image/*" capture="environment">`
- QR 스캔: `BarcodeDetector` API (미지원 브라우저는 `zxing-js` 폴백)
- 화면 꺼짐 방지: Wake Lock API

## 6. 사진 업로드 흐름

```
클라이언트 → API에 presigned URL 요청 (POST /uploads/presign)
          ← { uploadUrl, fileKey }
클라이언트 → S3에 직접 PUT (API 서버 대역폭 안 씀)
클라이언트 → API에 완료 통보 (POST /orders/:id/photos { fileKey, stage })
```
- 업로드 전 클라이언트에서 리사이즈(최대 1600px) + WebP 변환 → 현장 LTE 환경 고려
- EXIF 위치정보는 제거 후 업로드

## 7. 배포 · 인프라

### 개발
```yaml
# docker-compose.yml
services:
  postgres:  postgres:16
  redis:     redis:7
  minio:     minio/minio      # S3 로컬 대체
  api:       ./apps/api       # 핫리로드
  web:       ./apps/web
```

### 운영 (2가지 안)
| 안 | 구성 | 장단점 |
|---|---|---|
| **A. 클라우드 (권장)** | web=Vercel, api=Railway/Fly.io, DB=Neon/Supabase(Postgres), 파일=AWS S3 | 초기 비용 낮음, 배포 자동, HTTPS·백업 기본 제공 |
| B. 사내 서버 | Docker Compose + Nginx + Let's Encrypt | 비용 고정, 데이터 사내 보관. 단 정전·회선·백업 전부 직접 책임 |

> 고객 대상 서비스라 **24/7 가용성**이 필요하다. 사내 서버 운영 경험이 있어도
> 초기엔 A안으로 시작하고, 규모가 커지면 이관하는 쪽을 권한다.

### CI/CD
```
GitHub Actions
  push → lint + typecheck + test → build
  main 머지 → staging 자동 배포
  tag 생성 → production 배포 (수동 승인)
```

## 8. 보안 체크리스트

- [ ] 모든 통신 HTTPS 강제 (HSTS)
- [ ] **필드별 차등 암호화** — 상세주소·출입정보·전화번호만 AES-256-GCM, 도로명주소는 평문+접근통제 (문서 11 §4)
- [ ] 비밀번호 Argon2id 해싱 (기사/공장/관리자 계정) + 계정 잠금 정책 (문서 11 §5)
- [ ] Rate limiting: 인증 API 분당 5회, 일반 API 분당 60회 (`@nestjs/throttler`)
- [ ] SQL 인젝션: Prisma 사용으로 기본 차단, raw query 금지
- [ ] XSS: React 기본 이스케이프 + `dangerouslySetInnerHTML` 금지
- [ ] CSRF: refresh 쿠키 SameSite=Lax + 상태 변경은 Authorization 헤더 방식
- [ ] 파일 업로드: 확장자·MIME·크기(10MB) 검증, presigned URL 5분 만료
- [ ] 결제 웹훅 서명 검증 필수
- [ ] 관리자 계정 2FA (2차)
- [ ] 개인정보 접근 로그 (관리자가 고객 정보 조회 시 기록)
