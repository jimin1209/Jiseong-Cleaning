## 요구사항 (명세 9-2)

**"홈페이지가 그대로 보이는 상태에서, 아무 컴포넌트나 클릭하면 그 텍스트를 바로 편집"**
- 저장은 즉시 반영 금지: 편집 결과는 **1안/2안/3안 게시판**(제안 목록)에 저장 → 회의에서 채택 → 오케스트레이터/개발자가 반영
- 대상: 모든 컴포넌트의 텍스트

## 구현 지침

### 1단계 — 문구 데이터화
- 페이지에 하드코딩된 문구를 `src/lib/copy.ts`(신규) 같은 단일 콘텐츠 모듈로 추출 (키: `home.hero.title` 식 경로 키)
- 기존 컴포넌트는 해당 모듈에서 읽도록 변경. **화면 출력 결과가 1글자도 달라지면 안 된다** (순수 리팩터링)

### 2단계 — 편집 모드
- `/admin/edit` 라우트: 실제 홈페이지를 그대로 렌더 + 편집 오버레이
- 텍스트 요소 클릭 → 인라인 입력(또는 팝오버)으로 수정 → "제안 저장" 버튼
- 저장 시 `{키, 원문, 수정안, 제목(1안/2안/3안…), 작성시각}` 을 저장 (기존 inquiries 와 같은 저장 방식/DB 패턴 재사용)

### 3단계 — 제안 게시판
- `/admin/proposals`: 제안 목록 → 클릭하면 원문/수정안 비교 표시. 상태(제안/채택/반영) 필드.
- 반영 버튼은 만들지 않는다 (수동 반영 원칙 유지). "채택" 표시까지만.

### 접근 제어
- admin 라우트에 기존 admin/inquiries 와 동일한 접근 방식 적용 (있는 패턴 재사용, 새 인증 시스템 도입 금지)
