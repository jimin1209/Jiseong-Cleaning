## 구현 지침

### 1단계 — 문구 데이터화 (순수 리팩터링, 화면 결과 1글자도 불변)
- `src/lib/copy.ts` 신설: 경로 키(`home.hero.title`, `header.telLabel`, `footer.operator`, `services.rhythm.title`, `floating.kakao.notice` …) → 문자열. **하드코딩 문구 전부** 이 모듈에서 읽도록 컴포넌트·페이지 수정.
- site.ts(전화·주소·업종)·sample.ts(더미)는 그대로 두고 copy.ts 가 **참조** — 값 단일 출처 원칙 유지.
- JSX 구조·클래스·모션은 절대 변경 금지. 빌드 산출물 텍스트 diff 로 불변 검증(S7 핸드오프 3절의 검증 스크립트 방식 재사용).

### 2단계 — 편집 모드 `/admin/edit`
- 기존 admin 인증(proxy.ts basic auth) 그대로 적용되는 경로.
- 페이지 선택(4개) → 해당 페이지를 그대로 렌더 + 편집 오버레이: copy.ts 를 읽는 모든 텍스트 노드가 클릭 가능(호버 시 점선 하이라이트) → 클릭하면 인라인 입력/팝오버로 수정 → 화면에 즉시 미리보기(로컬 상태) → "제안 저장".
- **저장 단위는 "안(draft) 세트"다 (사용자 확정)**: 화면에서 여러 텍스트를 고친 뒤 한 번에 저장 — 제목은 기본 "1안·2안·3안…" 자동 증가에 **직접 입력으로 변경 가능**("가을 문구안" 등). 페이로드: `{안제목, 페이지, 작성시각, 수정목록: [{key, 원문, 수정안}]}` — inquiries.ts 저장 패턴(SQLite+Netlify Blobs)으로 `copy-drafts` 저장소 신설.
- 편집 화면 상단에 안 선택 바: [새 안] 또는 기존 안 불러와 이어서 수정·다른 이름 저장 가능. 현재 편집 중인 안의 수정 개수 표시.
- 구현 힌트: copy.ts 접근을 React Context(CopyProvider)로 감싸고, 편집 모드에서만 오버라이드 맵 + 클릭 핸들러를 주입하면 실페이지 컴포넌트 수정 없이 전 텍스트가 편집 가능해진다. 서버 컴포넌트 페이지는 편집 모드에서 클라이언트 렌더 래퍼로 감싸는 방식 허용(실서비스 라우트는 불변).

### 3단계 — 제안 게시판 `/admin/proposals`
- 목록(안제목·페이지·수정 개수·시각) → 상세: 키별 원문 vs 수정안 나란히 + 안 단위 상태(제안/채택/반영) 토글. "반영" 버튼은 만들지 않음(수동 반영 원칙) — 채택 표시까지만.
- admin/inquiries 와 같은 표 스타일 재사용.
